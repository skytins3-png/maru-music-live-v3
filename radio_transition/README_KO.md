# MARU RADIO 1.7 — 기존 앱 보존형 시험 설치

## 목적
기존 `MARU RADIO V1.6.x`에서 서명이 다른 APK를 덮어쓰면 Android가 설치를 거부합니다. 업데이트 문제를 이유로 기존 앱을 삭제하면 곡·설정·앱에 복사해 둔 음원이 지워질 수 있습니다.

그래서 이 시험판은 **업데이트 APK가 아니라 서로 다른 패키지 ID를 사용하는 별도 앱**입니다.

- 기존: `com.maru.radio.safev16` (그대로 둠)
- 시험판: `com.maru.radio.transition.v17` (추가 설치)
- 화면 명칭: **MARU RADIO 1.7 안전전환**
- 빌드: GitHub Actions `build-radio-transition.yml`의 `MARU-RADIO-V1.7-SAFE-PARALLEL-TEST` 테스트용 APK

## 실행 순서
1. **기존 MARU RADIO 앱을 삭제하지 마세요.**
2. Download / Suno 폴더에 본인 자작곡 원본 MP3/WAV가 실제로 남아 있는지 확인합니다.
3. 검증한 시험판 APK를 별도 설치합니다. Play Protect 경고가 있으면 경고를 우회하지 않습니다.
4. 새 MARU RADIO 앱 상단의 **Download에서 자작곡 다시 연결**을 눌러 파일을 선택합니다. 다중 선택 후 SHA-256 중복 제거를 적용합니다.
5. 앱에 오디오 경로가 연결되면 **진행자 대화 켜기 → 재생 → 다음 곡**으로 TTS+원곡을 테스트합니다.
6. BIGO 오디오라이브는 직접 시작하고, **BIGO 청취자 수신 테스트**에서 별도 청취기기가 진행자 음성과 음악 둘 다 듣는지 확인합니다.
7. 비교가 끝날 때까지 기존 MARU RADIO 앱과 원곡을 보관합니다.

## 데이터 이전의 한계 — 절대 과장하지 않음
- 서로 다른 앱 ID는 각자 Android 사설 디렉터리와 SharedPreferences를 갖기 때문에 **이전 앱의 100곡·장르 설정·타이머·내부 복사곡이 새 앱으로 자동 넘어오지 않습니다.**
- 다운로드 폴더에 존재하는 Suno MP3/WAV는 기존 파일을 삭제하지 않고 **새 앱에서 다시 선택**할 수 있습니다. Android가 반환하는 문서 읽기 권한만 보관하고, 일부 공급자가 지속 권한을 허용하지 않으면 새 앱에 별도 복사본이 만들어질 수 있습니다.
- 원래 앱의 `getFilesDir()/originals`에만 있는 곡은 새 앱에서 열 수 없습니다. 구 앱의 곡별 **BIGO용 저장**으로 Download/문서 폴더에 안전하게 내보낸 뒤 새 앱에서 선택해야 합니다. 이 작업은 사용자 조작이 필요하고 실제 화면에서 확인해야 합니다.
- **새 앱은 기존 앱/저장소에 아무 변경도 하지 않습니다.** 두 앱은 동시 실행 시 오디오 포커스 경쟁이 있을 수 있으므로 테스트 중 하나씩 재생합니다.
- 새 테스트판 또한 빌드마다 임시 디버그 서명이 바뀔 수 있어 향후 덮어쓰기 업데이트를 보장하지 않습니다. 장기 배포에는 소유자가 관리하는 안정적인 서명키와 공식 배포 검토가 필요합니다.

## 미완료
- BIGO가 외부 앱의 음악·TTS를 오디오 LIVE로 실제 송출하는지 (별도 청취 휴대폰으로 검증)
- BIGO 자동 댓글 수집·송신, 무인 자동 방송, 30명 독립 AI 가수 음색 생성과 그룹 합창
- Play Protect 인증, 사용자 기기 설치, 구 앱에서 수동으로 내보낼 수 없는 내부 데이터의 자동 마이그레이션

# MARU ONE 자동 업데이트: 현재 상태와 복구 불가 조건

## 이번 구현
- '🔄 MARU 자동 업데이트 · 지금 확인' 버튼, 매일 자동 확인 ON/OFF
- GitHub의 버전별 MARU ONE 릴리스만 조회하고 앱 ID `com.maru.musiclive.one` 확인
- 새 버전이 있으면 앱 안에서 APK를 다운로드하고 SHA-256을 검증
- 내려받은 APK 실제 패키지명, Android versionCode, 서명 인증서 SHA-256을 검사
- 일치하는 APK만 Android 설치 승인창에 넘김. APK를 몰래 설치하거나 앱을 삭제하지 않음
- 검증 실패 시 원본 앱/사용자 파일 유지. 기존 MARU RADIO EN 등 다른 앱 ID는 절대 혼합하지 않음
- 매일 업데이트 **확인**은 자동; 다운로드/설치 호출은 사용자가 선택. Android 설치 승인 필수

## 가장 중요한 실제 문제
2026-11-01 기준 이미 배포된 `MARU-ONE-SUNO-AHWAN-V3.2.24.apk`의
APK 서명 인증서는 SHA-256 `edf00be97de595d3f204aa48d4a56a61b3a9567292fc208706687660126fdb1e`.

앞서 생성된 `MARU_STUDIO_왼쪽목록_20261101_설치.apk`의 서명 인증서는
SHA-256 `f89c25f0ed086d48a812f5cc8b7593d93765736a184ad92b0e3603f8d18bcf9c`.
서명키가 달라 둘은 동일 앱의 업데이트가 될 수 없음.
**APK에 포함된 공개 인증서만으로 원래의 개인 서명키를 복구할 수 없음**.

이전 원본 개인 서명키를 확보하지 못하면, 지금 설치된 V3.2.24를 지우지 않고 덮어쓰는
APK를 만들 수 없음. 무리하게 설치하거나 기존 앱을 삭제하도록 안내하면 저장곡·설정이 손실될 수 있음.

## 자동 배포의 서명 보장
`.github/workflows/maru-one-stable-update.yml`은 다음 GitHub Actions secrets에서
원본 인증서와 일치하는 서명키를 읽어, 같은 인증서일 때만 새 APK를 배포함.

- `MARU_ONE_KEYSTORE_BASE64`: **원래** 앱에 쓴 keystore를 Base64 인코딩한 값
- `MARU_ONE_KEYSTORE_PASSWORD`
- `MARU_ONE_KEY_ALIAS`
- `MARU_ONE_KEY_PASSWORD`

이들 비밀값은 소스 코드/README/릴리스에 절대 포함하지 않음.
이미 배포된 APK와 서명 인증서가 다른 경우 빌드·공개 배포가 실패하도록 설계됨.
앱의 버전 번호와 versionCode는 해당 워크플로 실행 횟수에 따라 증가.
릴리스 노트의 `PACKAGE`, `VERSION_CODE`, `APK_SHA256`, `SIGNER_SHA256` 값을
앱이 검사해 잘못된 릴리스 설치를 차단함.

위 키가 없으면 **지금 업데이트 기능의 소스 코드는 완성될 수 있어도 원래 설치본 위에
올라가는 새 APK는 발행할 수 없다**. 기존 설치본은 그대로 유지.

## 실제 휴대폰 점검 필요
1. 같은 서명키를 찾아 비밀 저장소에 등록 또는 영구 서명키가 있는 새 앱 ID로 한 차례 이전하는 계획 마련
2. 해당 키가 살아 있는 릴리스의 SHA256/서명/패키지/버전 검증 및 다운로드
3. 기기에서 알 수 없는 앱 설치 출처 허용(필요한 경우), 설치 시스템 승인
4. 업그레이드 후 원곡/설정 보존과 이전/다음/목록 전환/BIGO 방송 동작 확인

**스튜디오 웹 디자인 변경은 GitHub Pages를 다시 열면 반영되는 웹 배포이므로 APK 재설치가 필요하지 않음.**
